# ADR NNNN: Short decision title

- **Status:** Proposed / Accepted / Rejected / Superseded / Deprecated
- **Date:** YYYY-MM-DD
- **Owner:** accountable role/name
- **Deciders:** accountable roles/names
- **Related:** issue, requirement, schema, experiment, risk, or open-decision ID

## Context

What decision is required, which constraints apply, and what happens if no decision is made? Include product scope, data/privacy, licensing, determinism, resource, interoperability, and migration context where relevant.

## Decision drivers

- Measurable driver and required threshold.
- Compatibility/ownership constraint.
- Reversibility and small-team operating cost.

## Options considered

### Option A

Evidence, prototype/benchmark environment, benefits, costs, risks, and license/data implications.

### Option B

Evidence, prototype/benchmark environment, benefits, costs, risks, and license/data implications.

## Decision

State the chosen option and the exact supported scope. Identify assumptions separately from proven evidence.

## Consequences

### Positive

- Consequence.

### Negative / accepted trade-offs

- Consequence and mitigation/owner.

### Privacy, security, legal, and licensing

- Data-flow/threat-model/retention/tenant/license/claim changes and required approvals.

### Reproducibility and resources

- Toolchain/model/config pinning, hardware profiles, benchmarks, and determinism impact.

## Rollout and verification

- Contract/schema/migration changes.
- Tests/evaluation and pass thresholds.
- Documentation/support matrix updates.
- Rollback trigger and method.

## Revisit criteria

A measurable condition or date that justifies reopening this decision.
