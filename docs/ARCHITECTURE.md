# OneClick2D 一期系统架构

- **状态**：提议；具体供应商和框架需 ADR
- **生效日期**：2026-07-21
- **首要原则**：先 Gate F，再产品化；小团队可运营；内容短期隔离；发布可验证。

## 1. 架构决策摘要

Gate F 使用本地、可丢弃、框架轻量的实验实现。Gate F 通过后，一期采用桌面优先的认证 Web 应用、模块化控制面和能力型 worker。摄像头跟踪与渲染在浏览器完成。

先比较两种最小方案：

1. 单一模块化部署 + 关系数据库任务表 + 事务 claim + 一个 worker runner；
2. 托管队列、对象存储和 worker。

只有故障测试或供应商语义证明需要时，才增加 outbox、DLQ、可续租 lease、独立队列或额外部署单元。禁止无证据引入 Kubernetes、Kafka、Redis、Temporal、服务网格和初始微服务。

## 2. 信任边界

```text
用户浏览器
  ├─ 上传/检查/修正/手动控制
  ├─ 摄像头 → 本地跟踪 → 参数 → 本地渲染
  └─ OIDC + HTTPS API
             ↓
模块化控制面 ── 持久控制状态
      │              （不含内容）
      ├─ 临时内容目录/私有对象
      └─ CPU/GPU worker（任务尝试范围）
                 ↓
       全项目验证 → 双导出 → 独立复核 → 授权下载
```

边界：浏览器/不可信输入、隔离解码区、控制状态/内容目录、worker、浏览器摄像头、下载包读取器。

## 3. 控制状态与内容分离

### 持久控制状态

可备份：不透明账号/项目/运行 ID、状态转换、策略版本、幂等记录、删除墓碑和内容无关审计。

### 临时内容目录

不得进入普通备份：对象键、源/衍生资源摘要、图像尺寸、内容关联元数据、尝试输出及导出。若供应商不能排除备份，需采用经恢复演练证明的加密擦除设计。

不允许跨账号内容去重。对象键不是授权依据。

## 4. 逻辑组件

### 浏览器

负责权利/保留说明、上传、状态、检查、P0 修正、手动预览、本地摄像头、下载和删除。不得持有队列、数据库或广域对象存储凭据。

### 控制面

一个代码库/模块化部署，模块边界包括身份、项目、接收、验证、生成、修订、导出、容量、删除及审计。跨模块通过应用契约，不做随意跨模块 SQL。

### Worker

接收不可变、版本化阶段规范；通过认证传输领取尝试；只写尝试前缀；提交候选结果。控制面验证类型、大小、像素/资源、摘要、契约、尝试身份和 fence 后原子发布。

### Renderer / Exporter

渲染器只消费验证过的 CIR，不依赖模型或 PSD 库。`.oc2d` 和 PSD 导出器是 CIR 的确定性投影，不能回写 CIR。

## 5. 上传与下载

上传会话称为“单次接收”，除非供应商能证明密码学意义的一次性。必须证明：create-only、固定大小/类型/校验（供应商支持时）、幂等 finalize、短到期、隔离区清理。

下载初期必须通过授权代理。只有供应商专项设计及并发、Range、重放和删除竞态测试证明：绑定账号、project revision、release/artifact digest 的每个短期授权（包括已发出和进行中的请求）都能真实撤销时，才可改为直传。数据库过期或下载后的对象删除不得视为授权撤销。

## 6. 任务及尝试语义

每阶段具有：

- 不可变输入和 stage spec；
- run/stage/attempt 身份；
- 稳定种子；
- 全部影响输出的代码/配置/模型/模板/契约摘要；
- CPU/GPU/RAM/磁盘/时间/输出上限；
- 取消检查和类型化结果；
- 临时目录清理；
- 默认无网络出口。

重试创建新 attempt，不覆盖旧输出。晚到、重复或失去所有权的结果不能发布。缓存键必须包含所有影响输出的身份。

## 7. 阶段 DAG

```text
INGEST_SCAN_NORMALIZE
→ VALIDATE
→ DECOMPOSE
→ PLAN_AND_BOUNDED_COMPLETE
→ SYNTHESIZE_LAYERS
→ MESH_AND_MINIMAL_RIG
→ VERIFY_PROJECT
→ COMPILE_PREVIEW
→ EXPORT_OC2D + EXPORT_PSD
→ VERIFY_EXPORTS
```

“ML 提议；确定性代码约束”：模型可估计适用性、蒙版、关键点、深度、有限隐藏像素和校准置信；确定性代码负责策略、本体、左右、拓扑、参数能力、范围、插值、验证、渲染、回退及发布。

## 8. 修订模型

任何权威修改创建新的不可变 project revision 和 payload digest，并使旧验证、警告确认、预览缓存和导出失效。受影响验证器重新运行，双输出都从同一新摘要生成。

警告确认绑定 finding code、finding instance ID、project digest 和 policy version，不允许用跨修订可变布尔值。

## 9. 内容生命周期

采用最早适用期限：

- 上传会话创建后即可删除；
- 用户删除：立即 `REVOKED`，目标 15 分钟内清空服务端内容清单；
- 成功验证输出：保证到 `terminal_at + 24h`，除非用户先删除；随后立即撤销授权，并最迟在 +15 分钟清空 inventory；
- 未完成上传：创建后 24 小时撤销，+15 分钟内清空；
- 失败/取消/验证终止/放弃：终态后 24 小时撤销，+15 分钟内清空，且清空不晚于上传后 72 小时。

删除清单覆盖源文件、标准化内容、中间件、每次尝试、缓存、分段上传、缩略图、导出和供应商副本。生命周期规则只是兜底。

## 10. 浏览器摄像头路径

从产品源加载固定版本跟踪器。明确进入 Preview 才请求权限。帧 → 本地特征 → 校准/置信门控/平滑/映射/钳制 → 渲染参数。

产品代码没有帧、裁剪、关键点、嵌入、校准或表情信号的服务端端点/包字段。测试在合成信号变化时监控 fetch/XHR/WebSocket/WebRTC、崩溃通道和应用管理的持久存储。拒绝摄像头时手动控制完整可用。

## 11. 安全基线

- 私有存储、TLS、精确 CORS、严格 CSP、CSRF/XSS 防护；
- 隔离、修补的媒体解码器和严格资源上限；
- 非 root 临时 worker、只读镜像、无主机挂载/容器 socket；
- 非可执行模型格式，禁止任意 pickle/custom op；
- 最小权限工作负载身份和短期凭据；
- ZIP/CIR/PSD 路径、计数、大小、压缩比、深度和摘要检查；
- 依赖/容器/IaC/密钥/许可扫描、SBOM 和构建溯源；
- 所有动作的双租户负例。

## 12. 可观测性和成本

只记录允许列表中的不透明 ID、状态、版本、原因码、耗时和粗粒度资源桶。禁止内容、文件名/路径、签名 URL、自由文本、精确内容哈希和摄像头字段。

接受 Generate 前预留最坏情况容量。指标分别报告每次合格开始的实际可变成本和每个验证成功结果的混合成本，失败/取消/重试不能排除。

## 13. 逐步提取触发器

- 单模块无法独立扩缩/隔离且有测量证据时才拆服务；
- 分支/补偿/人工等待使显式状态机不安全时才引入工作流引擎；
- 只有实测缓存/限流/pubsub 需要时才引入 Redis；
- 只有 GPU/多服务调度收益超过运维成本才引入 Kubernetes。

## 14. 架构验证

Gate F 证明自动假设；Gate 1 证明最小契约、任务所有权、隔离接收、删除、摄像头边界和双输出；Gate 2 证明生产形态阶段和恢复；Gate 3/4 证明负载、成本、可靠性、隐私、安全和运营。
