# 资源与关键路径计划

## 1. 原则

本计划以工作包、证据和人员容量为准，不以日期倒逼削弱质量门。Gate F 之前不建设生产规模基础设施。

## 2. 建议核心团队

| 角色 | 主要职责 | 最低投入假设 |
|---|---|---|
| 产品负责人 | 范围、用户研究、Gate 和声明 | 0.5–1 FTE |
| ML/图形工程师 ×2 | 拆层、补全、网格、绑定、评估 | 2 FTE |
| 全栈/平台工程师 ×2 | 编辑器、渲染、API、任务与存储 | 2 FTE |
| 质量/数据运营 | 素材、标注、评审、测试 | 0.5–1 FTE |
| 隐私安全/DevSecOps | 威胁建模、隔离、供应链、演练 | 0.25–0.5 FTE |
| 法律/许可顾问 | 数据、模型、品牌、地区和条款 | 按 Gate 预留 |
| PSD/动画顾问 | 图层规范、编辑器和运动质量 | 按里程碑预留 |

若只能提供约 5 FTE，应优先保持两名 ML/图形、两名平台/前端和一名产品/质量复合角色，同时采购安全、法律和 PSD 专项评审；不得把专项工作假定为“免费”。

## 3. 工作包与依赖

| 工作包 | 前置 | 输出 | 关键责任 |
|---|---|---|---|
| WP-0 立项与权利 | 无 | 章程、数据/许可、责任人 | 产品/法律 |
| WP-F 自动可行性 | WP-0 | Gate F 报告 | ML/图形 |
| WP-P PSD 可行性 | WP-0 | 写读/编辑器证据 | 平台/PSD 顾问 |
| WP-C CIR/包契约 | WP-F | v0.2、样例、独立实现 | 技术负责人 |
| WP-V 安全垂直切片 | WP-F、WP-C、WP-P | Gate 1 | 平台/安全 |
| WP-D 数据扩充 | WP-0，长期 | 60+、锁定集 | 数据/法律 |
| WP-A 自动 Alpha | WP-V、WP-D | Gate 2 | 全团队 |
| WP-B 私测与运营 | WP-A、法律准备 | Gate 3 | 产品/平台 |
| WP-R 发布证据 | WP-B、30 天暴露 | Gate 4 | 全团队 |

## 4. 关键路径

```text
责任人/预算/权利 → 20 个真实分层素材 → Gate F
→ CIR 最小契约 + PSD 双输出证明 → 安全垂直切片
→ 规模化权利数据 → 自动 Alpha → 独立验证集
→ 法律/隐私/品牌批准 → 私测暴露 → 锁定验收及发布评审
```

数据采购、编辑器席位/自动测试权利、模型权重条款和法律评审具有外部交付周期，应在 Gate 0 启动。

## 5. 资源预算类别

Gate 0 必须给出区间预算：

- 创作者委托、素材和标注；
- GPU 开发、评估和失败重跑；
- PSD 编辑器席位及兼容性测试；
- 模型/权重/托管服务；
- 安全评估和供应链扫描；
- 法律、商标、隐私及数据协议；
- 用户研究参与者；
- 运行、支持和事故预留。

## 6. 容量规则

- QA、数据运营、安全、法律、可访问性和支持必须显式进入估算；
- 同一责任人不得同时作为关键实现者和唯一批准者；
- 工作包连续两周缺少责任人或评审人时，视为进度风险；
- 外部依赖延期时先移动 Gate 或缩小范围；
- 不以删除测试、减少数据、跳过许可或降低硬门槛换取日期。

## 7. 30/60/90 天行动

### 前 30 天

- 关闭 Gate 0 核心决策；
- 完成权利明确的 20 项素材；
- 执行 Gate F 和 PSD spike；
- 决定继续、转向或停止。

### 31–60 天（仅 Gate F 通过）

- 冻结最小参数能力；
- 定义 CIR v0.2 和真实一致性样例；
- 建立内存内垂直切片、严格上传和双验证；
- 关闭技术栈、PSD 库、浏览器跟踪器和成本决策。

### 61–90 天

- 实现修订、修正和重新验证；
- 扩充 60+ 独立素材；
- 建立冻结评估、视觉回归、隐私和删除演练；
- 准备 Gate 2，而不是提前邀请外部用户。

## 8. 重新基线

每个 Gate 结束时按实测速度、数据到位情况、返工比例和外部依赖重新计算计划。任何日期变化必须记录原因、范围影响和责任人。
